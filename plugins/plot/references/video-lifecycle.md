# Video exports and workspace relocation

Requires backend contract 3 and a compatible MCP release. Use the server tool schema from `tools.describe` (await it inside execute) for current limits.

- `video_exports_delete({job_ids:[...],idempotency_key})` archives 1–100 exports; `video_exports_restore` reverses it. Inspect every results[] entry. Approved, published, workflow-evidence-linked, active and uncertain jobs are protected. This hides old candidates and disables their Review/approval; bytes and source versions are retained. Never promise disk reclamation or hard deletion.
- `video_projects_move({items:[{project_id}],destination_workspace_id,dry_run:true})` previews 1–20 projects without writes. It returns per-project plan_hash, counts or blockers. Commit with the returned hashes as expected_plan_hash, dry_run:false and a stable idempotency_key. A changed source/dependency requires a fresh preview. Repeat the exact key/input after an uncertain response; do not generate a new key to recover it.
- A batch is atomic per project, not across the entire batch. Report which entries moved and which failed. Finish/cancel active jobs, reconcile uncertain outcomes and release claimed requests before moving; never automatically repeat paid work.
- Relocation preserves project/version/job IDs, source and manifest bytes, hashes, comments and exact approvals. Workspace-scoped dependencies are copied/reused by metadata with the same private bytes; source assets remain available to other consumers. Published movement snapshots/audio travel with the project. Independent Character Studio editors remain separate resources; moving a video does not move their editable documents.
- Keep old immutable refs in source; project bindings resolve them after transfer. job_get projects old output IDs into the destination for inspection/media tools. Do not rewrite historical manifests or re-import generated media.
- Call project relocation directly. Workspace-scoped execute intentionally refuses cross-workspace moves. Other batch writes can use execute only when every target belongs to its scope.
- Verify destination listing, old/new export previews and exact hashes. Run a source check and a representative render after relocation, then share the same project Review URL. Cleanup has no authority to grant human approval.
